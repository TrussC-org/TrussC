# Header-inline state accepted by tools/check_header_state.py (CI).
#
# Each entry is a function-local static or an inline variable in core/include
# that a hot reload guest on WINDOWS gets its own copy of: the guest is a DLL,
# and a DLL compiles every header-inline function and variable into itself
# (docs/ARCHITECTURE.md, "One instance per process"). Linux and macOS share one
# copy between host and guest, so nothing below misbehaves there.
#
# Format:  <header> <scope>::<name>   # <category>: <reason>
#
#   harmless       a per-module copy changes nothing observable: a warn-once
#                  flag, a cache of derived data, a counter only one side uses
#   immutable      const data, the same in every copy
#   host-only      only code compiled into the host touches it (the core loop
#                  in TrussC.h, which the host's main.cpp instantiates, and the
#                  .cpp files of TrussC.lib); a guest's copy is never used
#   no-hot-reload  only on a path hot reload never takes (Android, headless)
#   known split    a Windows guest reads or writes its own copy, so the feature
#                  misbehaves in a Windows hot reload guest. Not fixed yet (a
#                  follow-up to #249). Do not add entries of this kind: define
#                  new state in a .cpp instead.
#
# New state that must be one per process (a singleton, a registry, a flag the
# host and app code both touch) does not belong here: define it non-inline in a
# .cpp (tcGlobal.cpp or a sibling) and declare an accessor in the header.
