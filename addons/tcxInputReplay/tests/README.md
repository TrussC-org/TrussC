# tcxInputReplay tests

`tests` is the ordinary addon console harness: `src/main.cpp`, `addons.make` and `local.cmake`, discovered by the addon test runner. It uses the core's headless sokol shim and initializes its dummy graphics backend for tcxImGui. It covers JSONL validation and round trips, long lines, large record counts and unsigned time/frame values, scaling in App coordinates (including framebuffer pixels), scene synchronization with a supplied clock, count/time ring eviction, unbounded default ring capacity, and rebasing after the initial mark is evicted. Explicit two-window mappings are tested for destination routing, missing/duplicate/closed mappings, configured/automatic flush paths, write failures and repeated stopped-flush warnings. MCP controls run through core JSON-RPC dispatch, including Control grant rejection, and through the loopback HTTP queue when available. The same smoke sequence also runs here through the core's virtual native Window producer, with DPI 1/2 and pixelPerfect off/on.

`../tests-display` is an opt-in display harness (`tests-display --display-check`; its default invocation skips) using the shared `tcDisplayTest.h` verdict helper. It also creates two native windows, flushes a ring after count eviction, and checks replay delivery to both destinations. It records scripted injected mouse/drag/scroll/key/character/touch/drop input, replays it through `Window::injectInput`, and compares all recorded fields and the `replayed` tag. A typed consumer at ImGui's priority verifies recording before consumption. It also checks repeated operations, real input mixing, marks, exclusion of its own replay, validation before injection, and cleanup finalization.

`b2WindowChecks.cpp` covers default/custom/disabled/repeated hotkeys, playback auto-hide and visibility restoration, file/ring toolbar save and cancellation, programmatic stop/flush without dialogs, and JSONL drop selection with normal app delivery and recording. It also checks setup-window ImGui attachment after initializing a second window, save failure/retry, unsupported pickers, staging location and POSIX permissions. Dialog choices and picker availability are injected through internal callbacks. `tests-display --toolbar-check` verifies the addon-owned frame; `--toolbar-app-check` verifies an app-owned frame. Both check toolbar drawing and exactly one ImGui frame per window draw. Native dialog interaction still requires a human; no automated native-dialog interaction API exists in this addon.

On Linux, run the display binary on Xvfb or an existing display. Use a private display number when starting Xvfb, and stop the Xvfb process by its PID. There is no addon API for starting a display server.

The normal build runner generates project metadata. In an offline worker where project generation is forbidden, stage the `emptyExample` CMake recipe with the relative core fallback `../../../core`, then configure/build each project through the prescribed build guard with `-DFETCHCONTENT_FULLY_DISCONNECTED=ON`. No addon dependencies need fetching.
