# tcxLua tests

Headless console test (no window). Lua files are written to a temp directory at
runtime.

XML bindings: empty-text serialization, escaped text and attribute round trips
through `Xml` and `parseXml` using the vendored pugixml.

Error-contained entry points (`tcxLua::call` / `tcxLua::runFile`):

- a syntax error, a missing file and a top-level `error()` in `runFile`, and a
  runtime `error()`, an index of nil, a nil function, a non-function value and
  `string.char(340)` in `call`, each return `false` without throwing; the state
  stays usable afterwards;
- syntax-error messages contain the file name; missing/unreadable files log an
  error, while empty files and files under Japanese paths load successfully;
- a valid file and a valid call return `true`, and call arguments arrive;
- repeated failing calls each log an error;
- the bundled `sketch.lua` accepts ordinary keys and ignores Shift / arrow keys;
- sol2's default script error handler still throws `sol::error`.

Lua `Node` surface (`TC_LUA_SKIP`):

- `Node.callAfterAsync`, `Node.callEveryAsync`, `Node.cancelAsyncTimer` and
  `Node.cancelAllAsyncTimers` are nil;
- `Node().callAfter`, `Node().callEvery` and `Node().cancelTimer` are still
  there.

The `Node` checks read the generated bindings (`src/generated/`), so they pass
once the bindings are regenerated from a `reference-data.json` that carries
`lua_skip` (see `tools/luagen-types/README.md`).

CI (`examples/build_all.py --addon-tests-only`) builds and runs this on every
push/PR; a non-zero exit fails the job. Run it locally with:

```bash
trusscli run -p .          # from this directory
```

The harness also runs the engine-only load/lint regressions in `engine/`.
They generate their source and bytecode in the test and need no display.
For a smaller build, configure that directory with CMake and run
`luaLoadBounds`; `-DUSE_LUAJIT=ON` selects the other bundled engine. This
checks large streamed source, large data/code/bytecode modules, streamed readers, finalizers, lint diagnostics, bytecode
range admission before allocations, and lint suggestion/depth/failure handling.

The finalizer case allocates 64 KiB per finalizer (2000 objects), and checks that
finalizers actually ran during compilation. The lifetime test also has a small
standalone ASan target, built with:

```sh
cmake -S engine -B engine/build-asan -DCMAKE_C_FLAGS="-fsanitize=address -fno-omit-frame-pointer" -DCMAKE_CXX_FLAGS="-fsanitize=address -fno-omit-frame-pointer"
cmake --build engine/build-asan --target lintGlobalLifetime
engine/build-asan/lintGlobalLifetime
```

`-DUSE_LUAJIT=ON -DTCXLUA_TEST_LARGE_BYTECODE=ON` additionally builds
`largeBytecode`, an optional valid-module round trip above 2 GiB. It writes a
temporary file and is excluded from the daily addon harness because of disk I/O.

The PUC `binaryMemory` target verifies emergency collection under an allocator
limit with reclaimable garbage. Both engine drivers check the binary buffer's
native GC accounting. `lintScanLifetime` compiles a generated copy of the lint
with a throwing set move constructor, modeling the MSVC STL; run it under ASan
with the flags above. It checks ordinary global reads across 65 source files.
The LuaJIT `embeddedBytecode` target exports `luaJIT_BC_trussc_embedded`, fills
it with a dump generated by the tested engine, and checks both the native
SIZE_MAX load convention and `require`. Its executable exports are enabled by
CMake. These small standalone targets do not require the framework or a GPU.
